# 2027 届测试求职冲刺

从今天开始并行投匹配岗位、做模拟面试、用订单系统补面试暴露的技术短板。第一阶段以拿到有效回复、笔试或面试为目标，7 天是执行周期，面试邀约时间取决于岗位和招聘流程。

## 1. 今天可以投什么

| 顺序 | 岗位 | 筛选依据 |
|---|---|---|
| 主投 | 软件测试、功能测试、初级接口测试的校招、补录和日常实习 | 职责以需求、用例、执行、缺陷、接口和回归为主 |
| 兼投 | 初级自动化测试、偏接口或 UI 回归的测试开发 | JD 接受基础脚本和项目经验，重点是编写维护用例；简历只展示已有证据 |
| 保底 | 实施、技术支持、偏运维实施 | 看是否接受应届、工作地及出差要求；重点准备 SQL、日志和沟通 |

先核对 2027 届资格、学历/专业、城市和截止时间；实习额外核对最早到岗、每周天数和可持续月数。首批目标 3–5 个匹配岗位，有合适的就投。两条渠道以实际供给调整，优先跟进快到截止且匹配的岗位。

引力波智谱校招强调测试方法和缺陷跟踪，卓望校招还列出关系型数据库、接口测试和一门语言，ASML 武汉实习明确要求 Python、Linux 和出勤。这些样本用于排列学习优先级，投递时以招聘页状态和个人资格为准。[引力波智谱软件测试](https://m.gamstek.com/campus-recruitment/job/20)、[卓望 27 届测试](https://job.ncss.cn/student/jobs/2Fx99fjrbWjEJnHfupihcX/detail.html)、[ASML 测试实习](https://www.asml.com/en/careers/find-your-job/software-testing-intern-j00352735)

## 2. 第一批投递与首面验收

- **投递前，限时 30 分钟。** 打开一页简历 V1，确认届别、联系方式、项目链接可用，保留自己做过且经得起追问的内容。用 `api-test-framework` 讲 pytest、requests、YAML 参数化和断言；公开 API 的 POST 是模拟响应。按已有内容先投，后续成果经独立验收再更新版本。
- **首面前争取练到。** 60 秒自我介绍、2 分钟项目讲解、10 分钟完成一道功能场景题、5 分钟口述一次接口排查、10 分钟手写两条只读 SQL。Linux 第一轮只要求能从文件中找出报错与上下文。提前收到邀约就正常参加，优先按 JD 准备。
- **项目证据。** 订单系统作为可控被测环境。仓库已有自动化、历史执行记录和配置。记录自己独立执行、编写和定位的工作，先把其中一条做成可演示的证据，再更新简历。Docker/PostgreSQL 和远端 CI 的运行状态以真实验收为准。

## 3. 理论和实际技术分开验收

| 优先级 | 理论口述 | 独立实操验收 |
|---|---|---|
| P0 功能测试 | 需求评审到发布、冒烟与回归、复测、严重度与优先级；用等价类/边界值、场景法、状态迁移解释取样 | 根据订单规则写 6–8 条用例，列出前置、数据、预期和优先级；实测至少 3 条，保留实际结果。发现偏差就提缺陷，全部符合就写测试结论 |
| P0 HTTP/接口 | 请求方法、参数位置、Header、JSON、Token；结合系统解释 401/403/409、超时和重复提交 | 用 Swagger 或 curl 走登录→创建→查询→异常，断言状态码、业务字段和副作用，保存脱敏请求响应 |
| P0 SQL | WHERE、JOIN、GROUP BY 的使用时机；接口成功后怎样验证落库 | 根据订单 ID 查金额和状态，再写一条订单与明细 JOIN；口述如何避免查错数据。只读验收 |
| P0 Python/pytest | 参数化、fixture、断言和失败信息各负责什么 | 独立新增一条订单回归，单条和所属套件各跑一遍。用临时错误断言观察失败，恢复后再跑通过并说明失败位置 |
| P1 Linux/排查 | 日志、进程、监听端口分别能证明什么；连接失败和 HTTP 错误的差异 | 用 tail/grep 找到指定时间或订单号的日志，再查对应监听端口，说明证据和下一步。真实 Linux 可用时用 curl、ps、ss 串联；Git Bash 只记录实际验证的文件和日志操作 |
| P1 Web UI | 定位、显式等待、Page Object，为什么元素可见不一定代表业务完成 | 跑订单项目现有 UI 用例，再独立补一个退出登录用例；有 UI 岗 JD 或反馈再提前 |
| P2 按 JD 加练 | 报告、CI 触发、环境隔离；岗位明确要求的性能或其他工具 | 完成一项与目标 JD 对应的可复现任务，再登记证据 |

每次只练一个自然板块，先答或先做，再看反馈。记录状态为「未验收 / 能解释 / 能独立做 / 能定位失败」。面试卡住时区分概念、执行判断、输入和练习不足，下次用变式复测。Python 与 SQL 用小题诊断，按结果补缺。

## 4. 前七天只推进一条业务链

| 时间 | 当天技术产出 | 投递与面试 |
|---|---|---|
| 今天 | 以“已取消订单能不能再支付”为题，口述风险、写首组用例和预期；挑一条操作记录证据 | 核对 V1，首批投 3–5 个；做 30 分钟模拟首面 |
| 第 2 天 | 手测创建→取消→再支付→回查；按项目规则核对拒绝响应及状态是否保持，再做 SQL 只读查询 | 跟进、继续投；针对昨天两处卡点各做一道变式 |
| 第 3 天 | 新增这条 pytest 回归，保存 diff 和真实输出 | 用一条请求、一个断言和一次失败讲 2 分钟项目 |
| 第 4 天 | 做一次日志/端口排查，形成「现象→命令→结果→判断」记录 | 第二次模拟，按目标 JD 增加现场用例或 SQL |
| 第 5–7 天 | 按反馈二选一：加固接口/权限用例，或补一条 Selenium UI；基于已有执行写半页测试总结 | 持续投，收到真面就按 JD 练；周末按漏斗调整下一周 |

第一张工单验收包括一张用例表、一条脱敏 HTTP 证据、一条 SQL 结果、自己写的一条 pytest 回归和两分钟讲解。手工步骤与 SQL 使用同一个本地服务和数据库。pytest 默认另启临时环境，由用例自行准备订单。订单仓库的运行步骤见 `enterprise-order-testing/README.md`。实操保留环境、操作步骤、结果和自己贡献的部分。

4 小时标准日：45 分钟筛选投递和跟进 + 105 分钟动手 + 30 分钟理论快问 + 45 分钟模拟/改答 + 15 分钟记录。只有 2 小时就用 35 分钟投递、60 分钟实操、25 分钟问答复盘。收到面试后，用约 90 分钟做 JD 定向准备，替换原当日模拟和部分实操。

## 5. 用反馈决定下一步

- **首轮模拟 30 分钟。** 1 分钟自介、4 分钟项目与追问、10 分钟用例设计、8 分钟 HTTP/SQL/排查、7 分钟反馈。每轮只定两个要修的问题，次日用不同题复测。对助手说「按冲刺计划模拟首面，一题一题问，先追问，最后统一反馈」即可开始。
- **真面后当天复盘。** 记题目、自己的原答、卡住的点、可复现的补练。若同主题在两次面试卡住，次日首个技术块专练它。面试方未给的评价记为未知。
- **投递没有进展。** 每周有足够匹配岗位时，先以 15–25 个有效投递作为工作量目标。已过约 5–7 个工作日且积累约 20 个匹配投递仍无约面时，先核对届别、地区、到岗、岗位职责、渠道和简历首屏项目证据，再用下一批对比。数量只作为复盘触发条件。
- **记录漏斗。** 每条记录岗位/城市、校招或实习、资格、渠道、投递日、简历版本、状态和下一次动作。区分已投、系统回执、人工回复、笔试、约面和下一轮。原始岗位链接、联系方式、截图和面试细节留在个人记录，Git 中同步可公开的计划与脱敏练习。

旧的 [70% 求职就绪学习包](70_percent_job_ready/README.md) 用来按主题找题和复盘。分数用于衡量训练进度，投递从今天开始。
