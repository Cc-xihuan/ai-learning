# 70% 综合验收

## 一、验收前置条件

- Python 和 SQL 已完成第一轮，并完成本包中的相关复习题。
- Linux、测试理论、HTTP 三个模块实操通过。
- `api-test-framework` V2 或 Web UI 自动化项目至少一个完成。
- 已准备自我介绍、项目介绍和投递记录。

## 二、笔试与口述（40 分）

从各模块题库随机抽取：

- 测试理论 8 题，共 12 分。
- HTTP/接口 6 题，共 10 分。
- SQL 4 题，共 6 分。
- Linux 4 题，共 6 分。
- Python/pytest/Selenium 4 题，共 6 分。

评分：答案正确只是基础；能结合项目或场景说明才能得满分。

## 三、现场实操（30 分）

### 任务 A：功能测试设计（10 分）

30 分钟内为“找回密码”功能分析需求并写出至少 12 条高价值用例，覆盖正常、异常、边界、验证码、频率限制、账号状态和安全风险。

### 任务 B：接口排查（10 分）

给定一条失败请求和日志片段，说明请求组成、状态码含义、可能责任层、需要补充的证据和复现步骤。

### 任务 C：Linux 排查（10 分）

在练习环境中找到服务进程、监听端口和错误日志，使用 curl 验证并形成简短结论。

## 四、项目验收（20 分）

选择 `api-test-framework` V2 或 Web UI 项目：

- 运行成功与可重复性：5 分。
- 结构和代码能解释：5 分。
- 测试场景和断言有价值：4 分。
- README、日志、报告和限制说明：3 分。
- 能回答追问并说明一次真实排错：3 分。

如果项目无法按 README 在新环境运行，项目部分最高 10 分。

## 五、求职验收（10 分）

- 60 秒自我介绍：2 分。
- 3 分钟项目介绍：3 分。
- 简历与仓库事实一致：2 分。
- 两次模拟面试记录：1 分。
- 有持续真实投递记录：2 分。

## 六、通过规则

- 总分至少 70 分。
- 理论基础不能靠项目分完全补偿：测试理论、HTTP、SQL、Linux均须达到各自 60%。
- 出现以下任一情况暂不通过：项目无法运行；简历明显夸大；不会解释自己写的代码；高风险命令/SQL执行缺乏确认；没有真实投递。

## 七、验收后的岗位范围

可以主投：功能测试、软件测试、初级接口测试、自动化测试助理/实习、实施测试相关岗位。

选择性投递：要求 Python + pytest + Selenium 且项目深度与当前证据相符的初级自动化岗位。

暂不主投：测试平台开发、复杂 Java 测开、性能调优、安全测试、移动端专项或要求独立搭建大规模 CI/CD 的岗位。
