# 模块 6：面试表达与投递

目标：把已经做过的事情变成可验证的简历证据和面试表达，同时持续获取真实反馈。

## 一、必须准备的表达

### 1. 60 秒自我介绍

结构：身份与求职方向 → 最相关技能 → 一个真实项目证据 → 当前行动 → 为什么匹配岗位。

不要讲家庭信息、长篇性格评价或没有证据的“精通”。

### 2. 3 分钟项目介绍

结构：

1. 项目解决什么问题。
2. 技术栈与结构。
3. 自己具体完成什么。
4. 覆盖哪些测试场景。
5. 遇到什么问题，如何定位和解决。
6. 当前限制和下一步。

### 3. 场景题回答框架

先确认需求和范围，再按功能、异常、边界、权限、状态、数据、兼容性、性能/安全风险组织。最后说明优先级、环境、数据和上线判断。

### 4. 不会的问题

明确说出已知边界，再给排查或学习方法。不能编造使用经历，也不能只回答“不会”。

## 二、面试验收题

### 测试理论

1. 为什么选择测试岗位？
2. 测试流程是什么？
3. 冒烟和回归有什么区别？
4. 如何测试登录、搜索、购物车、支付？
5. Bug 严重程度和优先级如何区分？
6. 开发认为不是 Bug 时怎么处理？

### HTTP/接口

7. 401 和 403 有什么区别？
8. GET 和 POST 有什么区别？
9. Cookie、Session、Token 如何理解？
10. 接口自动化应该断言什么？
11. 页面报错如何区分前后端？
12. 接口偶发超时怎么排查？

### SQL/Linux

13. `WHERE` 与 `HAVING` 有什么区别？
14. `INNER JOIN` 与 `LEFT JOIN` 有什么区别？
15. 如何安全验证 UPDATE/DELETE 的影响范围？
16. 如何查看最近 100 行日志并持续追踪？
17. 如何检查进程和端口？
18. 服务访问失败时你的排查顺序是什么？

### Python/pytest/项目

19. fixture 解决什么问题？
20. 参数化适合什么场景？
21. `requests.Session()` 有什么作用？
22. 你的项目为什么使用 YAML？
23. 你的项目当前最大的限制是什么？
24. 如果测试失败，你如何判断是用例问题、环境问题还是产品 Bug？

### Selenium

25. 元素定位有哪些方式，如何选择？
26. 显式等待和固定 sleep 的区别是什么？
27. Page Object 有什么作用？
28. UI 自动化为什么容易不稳定？

## 三、投递执行

- 每天 5～10 个有效岗位，功能测试/软件测试和初级接口自动化同步投。
- 自动化要求较高但核心条件匹配约 60% 的岗位也可以投。
- 明显要求测试平台开发、复杂 Java 工程或多年经验的岗位不作为主要目标。
- 每次投递记录公司、岗位、渠道、简历版本、日期、进展和反馈。
- 收到笔试/面试后，将真实题目加入错题库并调整下一周学习优先级。

- 简历中的每项技能都有学习或项目证据。
- 已产生真实投递记录。
