更新日期：2026-11-06

## 1. 这个“70%”代表什么

这里的 70% 不是掌握全部测试技术，而是达到以下可就业基线：

- 可以立即投递功能测试、软件测试、初级接口测试岗位。
- 能独立完成常见功能的测试分析、用例设计、执行、缺陷报告和测试总结。
- 能用 SQL、Linux、HTTP 和接口工具完成初级排查。
- 有至少一个能运行、能解释、与简历一致的自动化项目。
- 面对基础面试题、项目追问和测试场景题时，能用自己的话回答。

达到 70 分后继续投递和补强，不等待 100 分。70 分不代表已经适合测试平台开发、性能专项、安全专项、Java 测开或复杂 CI/CD 平台岗位。

70% 总验收必须同时满足：

1. 总分至少 70 分。
2. 测试理论、HTTP、SQL、Linux 四项均不得低于各自满分的 60%。
3. 至少一个自动化项目通过运行验收。
4. 能完成 60 秒自我介绍和 3 分钟项目介绍。
5. 已经真实投递，而不是继续等待“全部学完”。

## 5. 建议节奏（4 周，4～6 小时/天）

| 周次 | 主线 | 必须产出 |
|---|---|---|
| 第 1 周 | Linux + 测试理论 | Linux 排障记录、订单功能用例集 |
| 第 2 周 | HTTP/接口测试 + 项目表达 | 接口测试记录、Bug 报告、3 分钟项目讲稿 |
| 第 3 周 | Selenium | 可运行的 Web UI 自动化小项目 |
| 第 4 周 | 接口项目 V2 + 综合验收 | V2 代码、README、模拟面试、70 分评分表 |

每天固定顺序：

1. 投递 45～60 分钟：5～10 个匹配岗位，记录结果。
2. 当日主线 2～3 小时：只完成一个可验收产出。
3. 面试口述 30 分钟：基础题、项目题、场景题各 1 道。
4. 英语/离散数学按原计划安排，不挤占当天主线。
5. 复盘与 Git 推送 10～15 分钟。

## 6. 统一验收规则

- 理论题：先口述 1～2 分钟，再写关键词；正确率至少 80%。
- 实操题：必须保留命令、代码、运行结果或截图，只有“看懂”不算完成。
- 项目题：README 中必须写清目标、结构、运行步骤、结果和已知限制。
- 错题分类：概念理解错误 / 执行判断错误 / 粗心输入错误 / 练习不足。
- 同一类错误连续出现两次，下一次学习先安排针对性练习，不直接进入新章节。

## 7. 70% 阶段明确不做

- 不同时学习 Java、Appium、Playwright 和 Selenium 多套 UI 技术。
- 不深入性能压测调优、安全渗透、分布式测试平台或 Kubernetes。
- 不为了显得“企业级”而堆很多未被用例调用的目录和类。
- 不新建第二个重复的接口框架，优先升级已有项目。
- 不因还没达到 70 分停止投递；学习和投递必须并行。
