> 说明：本文件保留 2026-09-16 制定的历史计划。2026-11-06 起执行新版 [测试岗位 70% 求职就绪学习包](70_percent_job_ready/README.md)。

## 目标与当前证据

目标岗位是初级自动化测试、测试开发、软件测试；运维实施作为保底。

当前已经有真实证据：

- 能使用 Python 基础语法完成简单练习。
- `api-test-framework` 已使用 pytest、requests、YAML、日志、公共请求/断言封装和 HTML 报告，8 条用例通过。
- 做过 LLM API、Function Calling 和 AI 测试 Agent 预览练习。

当前主要缺口：

- Python 综合练习中仍有 `pass`、重复函数定义和缩进问题，说明“看过”还没有完全变成“独立写出”。
- 接口项目暂时缺少 fixture、真实鉴权与接口关联、数据库校验、Allure、CI 等企业常见证据。
- 暂无 Web UI 自动化项目证据。
- SQL、Linux、HTTP/网络、测试设计与面试表达还没有形成可验收产出。

## 学习顺序与产出

### 阶段 0：9/16，Python 基础收尾

只用现有 `day05_test.py` 做综合复习，不重看整套基础视频。

- 完成最贵商品、按城市搜索联系人、城市人数统计。
- 修复重复函数定义和缩进错误。
- 口述：列表与字典的区别、`return` 与 `print` 的区别、循环和条件如何组合、异常是什么。

验收：脚本从头到尾无异常；不看答案能改一个相近需求。

### 阶段 1：9/17～9/19，简历与项目表达

- 生成一页简历 v1，再按真实仓库修改为 v2。
- 准备 60 秒自我介绍和 3 分钟接口项目介绍。
- 项目介绍必须覆盖：为什么做、结构、自己的工作、遇到的问题、如何验证、下一步。
- 9/18 开始投递，不等待技术路线全部结束。

当前简历可写、但不能夸大的项目事实：

- Python + pytest + requests 搭建 REST API 自动化测试框架。
- 使用 YAML 管理测试数据并通过参数化覆盖多个查询场景。
- 封装配置、请求、断言和日志模块，生成 HTML 测试报告。
- 覆盖 GET、POST、404 等场景，当前 8 条用例运行通过。

数据库校验、Allure、CI、鉴权关联尚未完成前，不写成“已实现”。

最可能的坑：只背命令。每个知识点必须放进“发现问题 → 找证据 → 得出结论”的小场景。

### 阶段 3：9/25～9/30，Web UI 自动化

技术范围固定为 Python + Selenium + pytest，不临时换框架。

1. 启动浏览器、元素定位、基本交互和断言。
2. 显式等待、下拉框、弹窗、窗口与 iframe。
3. pytest fixture 管理浏览器生命周期。
4. Page Object：页面元素与测试用例分离。
5. 数据驱动、失败截图、日志与报告。
6. README、项目结构、运行说明和一次稳定回归。

验收：新环境按 README 能运行；至少 5 条有意义的用例；禁止用大量固定 `sleep` 假装等待；能解释为什么要 Page Object。

### 阶段 4：10/1～10/4，接口框架 v2

按价值排序逐项完成：

1. fixture 和公共前后置处理。
2. 一个鉴权或接口关联场景，将上一步响应数据用于下一步请求。
3. 数据库校验；若公开 API 不适合，使用本地 SQLite 构造可重复的校验场景，并在 README 说明边界。
4. Allure 报告与失败信息。
5. GitHub Actions 自动运行。
6. 更新 README 架构图、运行步骤、测试结果和已知限制。

验收：不是“目录很多”，而是每个新增模块至少被一个测试真实调用；所有测试可重复执行。

### 阶段 5：10/5～10/6，AI 测试基础

只学求职能用到的最小闭环：

- LLM/API、Token、Prompt、结构化输出的基本含义。
- Function Calling：模型提出调用，代码真正执行工具，结果再返回模型。
- 用模型根据接口描述生成测试点，程序做格式校验，人工确认后再执行。
- 能解释幻觉、隐私/密钥、提示注入、不可重复性、成本和人工兜底。

验收：一个小演示 + README；密钥只从环境变量读取；能说明“AI 生成不等于测试结论正确”。RAG、向量数据库、多 Agent 只理解概念，不在两天内硬做大项目。

### 阶段 6：10/7～10/10，面试冲刺

- 第一次模拟：自我介绍、测试理论、HTTP/SQL/Linux、Python、项目。
- 根据暴露的 3 个最大缺口定向补习。
- 第二次模拟：项目深挖 + 现场测试设计/简单编码。
- 简历终版、GitHub README 清理、演示顺序确认。

## 每日面试同步机制

从 9/18 起每天只练 3 题：

1. 一道基础题：测试理论、HTTP、SQL 或 Linux。
2. 一道项目题：为什么这样设计、如何排错、有什么不足。
3. 一道场景题：给一个登录/支付/接口，如何测试。

每题先口述 1～2 分钟，再看答案并修正。只收藏题库不算完成。
